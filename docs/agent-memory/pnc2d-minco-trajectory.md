  `core/goal_checker.hpp`（xy/yaw 分开 + `stateful` 锁存）+ `local/heading_shim_planner`
  （实现已有 `LocalPlanner` 接口的**装饰器**，内部持有 primary ⇒ local 节点零改动）。
  ★ 关键不是搬功能而是**换律**：恒速 `ω=sign(e)·omega_rot` + `clamp(ω, ω_prev±α·dt)` +

## 关键架构决定
- MINCO 放**全局节点**（唯一有全图 SDF/梯度的地方；已订 odom、已有 `ClearanceField`）
- ★★ **参数化必须用 (θ, s)，不是 (x, y)**（2026-09-24 读原版代码后改的；原版 `MINCO_S3NU` /
  `Trajectory<5,2>`：`p=(θ,s)`、`v=(ω,v)`、`a=(α,a)`，jerk 为输入，XY 靠 **Simpson 积分**
  `x=x0+∫cosθ ds` 还原，`traj_anal.hpp` 里**没有 ICR 项** ⇒ 差速就是它的退化情形）。
  好处：yaw 独立决策（原地转天然，`align_*`/`goalYawAlign` 那套降为兜底）、运动学线性
  （约束直接是 `|ṡ|≤v_max`/`|θ̇|≤ω_max`/`|θ̈|≤α_max`）、**无 κ 噪声问题**、
  终点朝向是状态约束。代价：XY 是派生量 ⇒ **终点 XY 必须 ALM**
- ★★ **剖面靠"参考点的时序"起作用**：原版 `matrix_q=[15,15,0,1]` 里 **v 权重 = 0**
  （`dQ[dimx] += Q[2]`），`dref(0)=v` 不进代价、ω 参考也没进代价 ⇒
  **光传 `traj_v` 数组而 MPC 仍自己算时间 = 剖面根本没传**；必须按上游 `t` 采样
- ★★ **速度剖面归 MINCO（用户 2026-09-24 纠正，我原来说"底盘专有"是错的）**：
  剖面 = 时间参数化，与几何是同一优化问题的两个面（κ↔v 硬耦合、净距↔v 硬耦合、
  时间分配就是运动学可行性的结论）⇒ **必须传输给 MPC**，MPC 从"算速度"退成
  "跟速度(前馈) + 底盘钳位 + 末段停靠"。
  底盘层只留**执行**（ω 死区、cmd_vel 标定、stop_coast、brake_acc）与**到点/对正策略**。
  限速区/限速将来也进 MINCO（地图语义），不进 MPC ⇒ 那套 `zoneSpeedLimitAheadFromProjection` 可退休
- 传输：保留 `nav_msgs/Path`（RViz + `corridor_width[]` 下标对齐），srv/action 加
  `float64[] traj_t/traj_v/traj_omega`，**长度不匹配 = 整体视为无剖面 + WARN**；
  末段降到 `traj.goal_v`(≈`approach_speed`) 而非 0（否则两套减速剖面打架）
- 开关 `traj.type: none|minco`（默认 none = 现网零变化，可 A/B）
- 失败策略：MINCO 无解/超时/终检不过 ⇒ **降级用 A\* 原路径**，任务照走

### ★★ 两个把轨迹搞崩的坑（都实测取证过）
1. **Eigen 的 `MatrixX2d` 是 `(Dynamic, 2)`**，`MatrixX2d m(2, 53)` 在 Release
   （NDEBUG，断言被关）下**静默变成 2×2** ⇒ `m(0,52)` 越界读。MINCO 的内点必须是
   `Matrix<double, 2, Dynamic>`；`solveMinco` 里加了行列数校验。
2. **路点取法必须是"时间等分 + 弧长按剖面走"**。反过来（弧长等分 + 时间按剖面）
   会让每段时间在 3~4 倍范围变化而 s 增量均匀 ⇒ 带状系统解出剧烈摆动：
   实测未缩放解中段 **2.15 m/s**（巡航 0.6）、**s 冲过终点 3 m 再回来**、
   净距 −1.0（跑到图外），且与路点密度（0.15/0.5/1.0 m）无关。
   改对后：直线 8 m ⇒ 净距饱和 1.0、max_v 0.66、终点 0.0000 m。

### 时间参数化（实际实现，**不是**原计划的 L-BFGS 调 T_i）
1. **曲率感知速度剖面**（解析，无迭代）：`v_cap = min(v_ref, ω_max/κ)`（三点式 κ，±0.30 m 基线）
   → 前后向加速度扫描 `v_i = √(v_{i-1}² + 2·a_cp·Δs)`，`a_cp = 0.5·a_max` → 弧长-时间映射。
   弯道**局部**减速而非全路变慢（折角 时间×19.8 → 1.03 的关键）。
2. **路点 = 时间等分 + 弧长按剖面走**（见上面坑 #2）。
3. **终点 XY 修正 = 数值 Jacobian + 阻尼最小二乘**（不是 ALM；ALM 留作冗余，免迭代调和）。
4. **时间缩放**保留为安全网（解析 `T_i←k·T_i` ⇒ `v/k`、`a/k²`，几何不变）；正常应退出 k≈1。

### ★★ 三、"轨迹比剖面慢 1.8 倍"的真根因（**不是**多项式跟不上，我一度诊断错）
1. **端点速度被地板抬高**：剖面写 `v_prof[0] = max(v0p, v_floor)`。车静止起步（v0p=0）
   被抬到 `v_min=0.2` ⇒ 剖面声称"0.084 m 用 0.40 s"，而从静止、|a|≤0.25 走完 0.084 m
   **至少**要 `√(2·0.084/0.25)=0.82 s`。少算的时间只能靠超限加速度补：实测
   `max|a|=1.567 ≈ (2·0.084/0.4²)×1.5 = 6.3·a_cp` ⇒ 缩放 k=1.78 ⇒ 8 m 直线 27 s、max_v 0.508。
   ⇒ 端点**如实**用请求给的边界速度（0 就写 0）；`v_min` 地板只管**内部**点。
2. **t→s 线性插值**：`v ∝ √s` 是**凸**的 ⇒ 线性插值**高估** v（剖面说 s=0.053 用 0.39 s，
   真实 0.65 s）⇒ 路点被放到**物理上到不了**的位置 ⇒ 缩放仍乘 1.45。
   ⇒ 改用**恒定加速度**的精确关系（`v²=v₀²+2aΔs`、`Δt=(v−v₀)/a`），s→t 与 t→s 互逆且精确
   （区间时长 `2Δs/(v₀+v₁)` 与 `(v₁−v₀)/a` **恒等**，不是梯形近似）。
- 实测：k **1.776 → 1.006**；8 m 直线 **20.59 → 12.56 s**、max_v **0.508 → 0.900**；
  剖面意图 12.491 vs 实得 12.560（比 **1.01**）
- ★ 教训：**先取证再改算法**。逐段打印"剖面意图 vs 实得"一眼就看出差在**首段**（端点条件），
  而我先前的结论是"多项式跟不上分段剖面形状"（错），差点去重写没问题的东西。

### ★★★ 三点五、剖面**看不见"转向"**（现场：5.62 m 走出 144.75 s、max|v| 0.070 m/s、时间缩放 ×10.10）
与"端点速度"同一类错误（**剖面看不见某个状态约束**）。两条线索都能直接算：
- `折线max|κ|=14.0` 是**伪造的**：i=0 处 `atS(s−win)` 与 `atS(s)` 是**同一个点** ⇒
  `atan2(0,0)=0` 被当"入方向" ⇒ 转角被算成"相对 0 朝向的绝对朝向"。14.0×0.15 m = **2.1 rad**。
- 未缩放 `max|ω| = 0.65×10.10 = 6.57` rad/s（限 0.65）。`θ(0)=req.start.yaw` 是**车的实际
  朝向**（odom），而 **A\* 从当前格朝任意方向迈第一步、不看车的朝向** ⇒ 两者差 2.1 rad。
  曲率只描述折线自己 ⇒ **完全看不见**这个差 ⇒ 不给它分配时间 ⇒ 2.1 rad 只能在一个
  `T_step`(0.4 s) 内转完 ⇒ ω=5.25、多项式 6.57。
- 掩盖成"随机"的一条：`max(v_floor, min(vcp, ω_max/κ))` 里 κ=14 处上限 0.046 被地板 0.2 抬回 4 倍。

修法（三处，缺一不可）：
1. **剖面判据从 θ(s) 直接推**（不再从折线几何另算曲率）：θ(s) 按"与路点同一套规则"生成
   （起点 = start.yaw，其余按切线解缠）；上限取两个 κ 的**大者**：**逐段必要条件**
   `v ≤ ω_max·Δs/|Δθ|`（对离散 θ 精确成立，起点朝向差天然落在 i=1 段）+ ±tan_base 窗口
   （只当**平滑偏好**）。`v_min` 地板降级为**告警阈值**，不得覆盖运动学上限。
2. **路点朝向做转向速率限幅**，律直接借用 **Nav2 rotation_shim 三件套**
   （`clamp(e/Δt,±ρω_max)` → `clamp(ω_prev±ρ_α α_max Δt)` → `sign·min(|ω_des|,√(2ρ_α α_max|e|))`）。
   **硬 clamp 试过不行**：斜率从 ρω_max 直接掉 0 ⇒ α 冲激 4.34 = 1.7×α_max ⇒ 缩放再乘 1.32。
   转不完的部分 = 轨迹滞后切线 = **起点原地转**（实测头 1 s 位移 0.001 m）。
3. **`ρ_w = 0.6`，剖面与限幅必须用同一个系数**：C² 多项式在路点**之间**的 ω 峰值过冲到
   路点斜率的 ~1.6 倍（与 `acp = 0.5·a_max` 同理）。限幅取 0.8 时多项式 ω 反到 1.26×ω_max
   ⇒ 缩放乘 1.26。**两处系数不一致 = 两套剖面**。

实测（新用例 `StartHeadingMismatchIsTurnedWithAllocatedTime`，起点差 120°）：
`max|ω|` 0.618/0.65、`max|α|` 2.497/2.5、`k=1.038`（不是 10.10）、时长 **144.75 → 27.15 s**、
头 1 s 位移 0.001 m、求解 1.6 ms。判据 **9 用例全绿**、整包 11/11。

新增两条**可行动**诊断（写进 status note，>20° / <v_min 时才报）：
`⚠ 起点朝向与路径首段差 N°`、`⚠ 因转向速率限制被迫最低速 x m/s @s=…`。

```
机制① 关（默认）      ：端点下限 0.622 → 实际达成净距 0.607 / 缺口 0.015
```
**结构性原因**：降低目标 ⇒ SDF 罚提前归零 ⇒ 锚定项把路径拉回来 ⇒ **实际达成净距变低**。
而终检查的是**实际净距** ⇒ 开它只会让拦停**更频繁**。（原版用它对付"起点在死角落"，
与我们的判据方向相反。）
⇒ `smooth_safe_ratio` 默认 **0 = 关闭**（同 `max_length_m: 0 = 不截断` 约定），保留能力+数据+开关用例。
⇒ 保留更诚实的指标 `smooth_shortfall = max(逐点目标 − 实际)`（0 = 达标）——正是它让我量出反效果。
⇒ 逐点目标框架 `SmoothCtx::d_tgt` 按**点索引**给目标（实时弧长是位置的函数，忽略其导数会失真）。

★ 真正的杠杆（`AvoidanceWeightVsAchievedClearanceIsMonotoneAndMeasured`，钉住"加大权重不得让净距变小"）：
`w_sdf 2/4/8/16 → 达成 0.607/0.611/0.615/0.619 m，偏移 0.036→0.039 m` ——
收益单调但饱和、代价几乎不变 ⇒ 真看到拦停可调到 8；**先留 2.0**（更高权重在拥挤图里
可能把路径推进别的障碍，这个风险没量过）。

★★ **拦停率的关键认识**：M3 终检**含朝向**，比 `R_circ + margin` 那条**中心线**判据**宽松得多**
⇒ "达成 < R_circ" **不等于**终检失败（贴墙用例：达成 0.439 < R_circ 0.4717，终检**通过**）。
目前看到的失败都是**几何本身勉强**（实测那条：真实净距只剩 5 cm 而车长 0.7 m）。
⇒ 拦停率必须用**真实地图数据**量，不能靠合成几何外推。

### ★★ 四、终点修正的**秩亏**（另一个"冻住"的坑）
折角末端 0.8 m 是沿末端朝向的**直线** ⇒ `∫cosθ·ds` 与这段 s 分布无关 ⇒ `∂p_end/∂s_k ≡ 0`，
J 第一列全零、`det=0`（实测 `J=[-0.000 -0.302; -0.000 -0.007]`）。旧代码一见 |det|≤1e-6 就掉进
"沿末端切线的 1 维退化分支"，而那分支只能沿末端朝向挪 `s_total`（π/2 ⇒ 只能动 y），
残差却全在 x 上 ⇒ **12 次迭代残差冻在 0.0274 m**。
⇒ 自由变量补 `s_total`（J 变 **2×3**）+ **阻尼最小二乘** `(JᵀJ+λI)⁻¹Jᵀr`（恒可逆，λ→0 退化
最小范数解，秩亏方向自动不动）⇒ **一步收敛 0.0274 → 0.0005 m**。

### ★★ 五、起点压在障碍上必须**拒绝**（新增 `TrajStatus::kStartBlocked`）
与 `astar_planner.cpp` 虚拟起点守卫**同口径**（"余量带内 ⇒ 换虚拟起点；真实轮廓都放不下 ⇒
停车报错交人工"）。旧行为会从柱子内部算出一条 `30段/80.2s/时间×6.85` 的轨迹：净距统计与

**只拒"真实轮廓（safe_margin=0）压上"**；落在余量带里必须照常规划（拒了 = 不可恢复死局）。

### ★★ 六、轮廓判定**把位姿吸附到格心**（已实测，未修，写进头文件 R13）
`rectOffsets` 只用机体系 offset 建矩形（相对"当前格中心"），**丢掉 (wx,wy) 的亚格偏移**
⇒ 判定误差 **±半格**（res=0.10 ⇒ ±5 cm）。实测同一格内 y 从 2.61 扫到 2.70，净距**恒为

### 性能口径（"感觉太耗时间"的答案）
- 净距统计**曾逐积分点**（integrate_dt=0.01）做轮廓检查：一次 `signedClearanceAt` ≈16 次轮廓
  检查 ≈600 次格查询 ⇒ 5000 点 ≈150 ms，**这才是主因**。改到**输出采样**（0.05 s ≈ 3 cm，
  与下发 MPC 的轨迹同密度）⇒ 111 ms → 29 ms。
- 剩余统计成本 ≈ 15 µs × 时长/0.05（O(时长)，不是 O(路径长)）⇒ **缩短时长才是总杠杆**。
- `traj.max_length_m = 40`：只优化前 40 m（MPC 前瞻 1~2 m）；截断时终点是**途经点**（不减速不对正）。
- ★ 回答用户："**整段 A\* 只优化一次**（结果缓存，MPC 只跟踪，不在控制环里）"。
- ★ **换 B 样条：本期不做**（根因不在多项式族，修掉剖面后 MINCO 已逐段跟随，比 1.01）。
  记作升级路径：均匀三次 B 样条的 `v(t)=Σ(ΔP_i/Δt)B_i`、`a(t)=Σ(Δ²P_i/Δt²)B_i` ⇒ 由**凸包性质**
  `max|v| ≤ max|ΔP_i|/Δt`、`max|a| ≤ max|Δ²P_i|/Δt²` 是**可证明的界**；且它是**逼近**不是插值，
  最后一个控制点直接就是目标 ⇒ 终点 XY 精确（秩亏那套完全不需要）。
- ★ **分段不是加速手段**（用户问"会不会加快"）：拆 K 段总 FLOPs 一样；能省的只有"终点修正只在
  最后一段做"。真实价值在 M6 **重规划时只重算受影响的那段**（缓存）。
